# v3.3.0 · 2026-10-25

## 中文

### 主要变化

- **失效绑定自愈**：命名会话绑定的节点拨号失败时，本次请求会额外重新选一次节点（即使 `retry_enabled: false`），成功后把绑定迁到新节点；额外那次也失败则保留原绑定，避免一次抖动就悄悄更换出口 IP。
- **失效节点立即拉黑**：上述失败同时把该节点拉黑，真实传输故障（握手/证书/协议错误、拨号被拒）按 `blacklist_duration` 直接生效，不必等 `failure_threshold` 累计；`429` 与超时/连接重置/`503` 仍只走对应冷却。新增 `pool.blacklist_failed_pin`（默认 `true`）可关闭立即拉黑、只保留自动换节点重试，面板「绑定节点拨号失败时立即拉黑」同款开关。
- **会话 ID 上限 100**：`[A-Za-z0-9_-]{1,100}`，代理认证、管理 API 与 WebUI 校验收口一致。
- **绑定空闲续期修正**：只有成功拨号才刷新 `sticky.session_ttl`，失败连接不再给死绑定续命，LRU 顺序与过期时间重新对齐。

### 典型现象

修复前：某个会话 ID 第一次绑定到的节点后来失效，该 ID 会一直返回 `502`，而其它会话正常；`wang.abc_1` 与 `wang.abc-1` 表现不同纯属绑到了不同节点，与会话 ID 里的下划线/短横线无关。

修复后：

```text
1. 拨号仍走原绑定节点 → 失败
2. 本次请求额外选一个健康节点重试 → 成功，绑定迁移（switch_count + 1）
3. 原节点按 blacklist_failed_pin 立即拉黑（默认 24h），其它会话不再被分到它
4. 若第 2 步也失败 → 保留原绑定，下次连接继续尝试；连续失败不再续期 TTL
```

需要提前放回节点：面板节点列表，或 `POST /api/nodes/{tag}/release`。

### 配置

```yaml
pool:
  failure_threshold: 3
  blacklist_duration: 24h
  transient_cooldown: 60s
  rate_limit_cooldown: 60s
  retry_enabled: true
  retry_attempts: 3
  blacklist_failed_pin: true   # 命名会话绑定节点拨号失败时立即拉黑（429/超时类仍只冷却）
```

```yaml
listener:
  username: wang
  password: "1234"   # 仅为示例，请更换
sticky:
  session_enabled: true
  session_ttl: 24h
```

会话 ID 现在支持 1–100 个 `[A-Za-z0-9_-]` 字符；`基础用户名 + 点号 + ID` 仍需落在 SOCKS5 的 255 字节用户名上限内。

### 升级注意

1. 备份挂载的配置目录并保留 `node_ports.json`；升级不会改动已有会话绑定（但重建容器会清空内存绑定）。
2. Compose 可固定 `image: ghcr.io/jasonwong1991/easy_proxies:3.3.0`；镜像发布任务完成后执行：

   ```bash
   docker compose pull easy_proxies
   docker compose up -d --force-recreate easy_proxies
   ```

3. 旧版本（≤3.2.0）对超过 64 位的会话 ID 仍返回 `407`；`blacklist_failed_pin` 对旧版本无效，需要在升级后的二进制上生效。
4. 工具链要求 **Go 1.26.10+**（修复 `crypto/x509` 的 GO-2026-6809），Docker builder 同步固定为 1.26.10。
4. `blacklist_failed_pin: false` 只是关闭“立即拉黑”，自动换节点重试仍然生效；节点会回到 `failure_threshold` 累计逻辑。

交付延续 GitHub 源码归档和 GHCR `linux/amd64`、`linux/arm64` 镜像，不附独立二进制下载资产。

## English

### Highlights

- **Stale pins heal themselves**: when a named session's bound node fails to dial, that request gets one extra selection even with `retry_enabled: false`, and a successful re-route migrates the binding; if that attempt fails too, the original pin is kept so a single blip does not silently change the exit IP.
- **Failed node blacklisted immediately**: the same failure blacklists the node. Transport faults (handshake/cert/protocol errors, refused dials) apply `blacklist_duration` right away instead of waiting for `failure_threshold`; 429 and timeout/connection-reset/503 keep their cooldowns. New `pool.blacklist_failed_pin` (default `true`) turns the immediate blacklist off while keeping the re-route; the pool settings panel exposes the same switch.
- **Session IDs up to 100 characters**: `[A-Za-z0-9_-]{1,100}`, applied consistently in proxy auth, the management API, and WebUI validation.
- **Idle renewal fixed**: only a successful dial refreshes `sticky.session_ttl`; failed attempts no longer keep a dead pin alive, and LRU order stays aligned with binding expiry.

### Typical symptom this fixes

Before: a session ID whose first binding later died kept answering `502` while other sessions worked. `wang.abc_1` and `wang.abc-1` behaving differently was never about the underscore or hyphen — they had simply pinned different nodes.

After:

```text
1. dial the bound node -> fails
2. this request tries one fresh healthy node -> succeeds, binding migrates (switch_count + 1)
3. the old node is blacklisted per blacklist_failed_pin (default 24h); other sessions stop seeing it
4. if step 2 also fails -> the pin is kept, the next request retries; repeated failures no longer renew the TTL
```

Release a node early from the node list in the panel or with `POST /api/nodes/{tag}/release`.

### Upgrading

1. Back up the mounted configuration directory and keep `node_ports.json`; existing bindings are untouched, but recreating the container clears in-memory bindings.
2. Pin `image: ghcr.io/jasonwong1991/easy_proxies:3.3.0`, then after the image workflow finishes:

   ```bash
   docker compose pull easy_proxies
   docker compose up -d --force-recreate easy_proxies
   ```

3. Builds ≤3.2.0 still answer `407` for session IDs longer than 64 characters, and ignore `blacklist_failed_pin`; both need the upgraded binary.
4. The toolchain requirement is **Go 1.26.10+** (fixes `crypto/x509` GO-2026-6809); the Docker builder is pinned to 1.26.10 as well.
4. `blacklist_failed_pin: false` only disables the immediate blacklist — the automatic re-route stays, and the node returns to the `failure_threshold` path.

Published as source on GitHub plus `linux/amd64`/`linux/arm64` images on GHCR, without standalone binary assets.
