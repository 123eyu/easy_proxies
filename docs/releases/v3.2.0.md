# v3.2.0 · 2026-10-12

## 中文

### 主要变化

- **主端口命名会话**：HTTP/SOCKS5 使用 `用户名.sessionID` 固定 TCP 上游节点，失败时按池策略切换；普通用户名保持原调度，旧来源 IP 粘性端口继续兼容。
- **更易用的面板**：会话 ID/接入链接生成与复制、绑定查询和重置、节点搜索/状态筛选、移动布局、按需分批展示，以及明确的操作失败反馈。
- **可靠性修复**：配置事务与原子保存、订阅失败回滚和手动刷新、生命周期并发、人工禁用保留、真实 HTTP 健康判断、稳定端口/VMess 身份迁移、GeoIP 转发/更新和管理认证。
- **交付与性能**：Go 1.26.9 工具链及兼容依赖更新，新增发布前质量门禁；会话查找、日志写入和大节点列表渲染优化。详见 [CHANGELOG](../../CHANGELOG.md) 和 [审查报告](../project-review-2026-10-11.md)。

### 会话示例

listener 用户名为 `wang`、密码为示例 `1234` 时：

```text
http://wang:1234@127.0.0.1:2323            普通池调度
http://wang.account01:1234@127.0.0.1:2323  命名会话 account01
socks5h://wang.account01:1234@127.0.0.1:2323
```

`sessionID` 支持 1–64 个 `[A-Za-z0-9_-]` 字符；默认空闲 TTL 为 24h、容量为 10,000。固定的是上游节点，不保证服务商公网出口 IP 永不改变；既有连接不迁移，已发送的业务请求不重放。订阅刷新/核心重载可保留相同身份绑定，进程重启会清空会话。详细边界见 [会话路由指南](../session-routing.md)。

## English

### Highlights

- **Named sessions on the main port**: `username.sessionID` keeps a TCP upstream node across HTTP/SOCKS5 connections, with pool-policy failover. The bare username retains ordinary scheduling; the legacy source-IP sticky port remains compatible.
- **Usability**: session/link generation and copying, binding inspection/reset, node search/status filters, mobile layout, batched rendering, and explicit operation errors.
- **Reliability**: transactional configuration saves, subscription rollback/manual refresh, lifecycle concurrency, preserved manual bans, actual HTTP probe validation, stable port/VMess identity migration, GeoIP handling, and live management authentication updates.
- **Delivery/performance**: Go 1.26.9 and compatible dependency updates, pre-publication quality gates, faster session lookup/log writes, and lighter large-node views. See the [changelog](../../CHANGELOG.md) and [review report](../project-review-2026-10-11.md).

### Upgrade notes

- Back up the mounted configuration directory and retain `node_ports.json`. Pin Docker to `ghcr.io/jasonwong1991/easy_proxies:3.2.0`, then pull/recreate after its image publication job completes using the commands above.
- Source builds require **Go 1.26.9+**; Docker uses 1.26.9. Use the README's production tags for optional protocols/traffic statistics.
- Management password changes apply immediately and revoke existing logins: sign in again before applying pending changes.
- Prefer directory mounts for atomic replacement. Individual-file mounts use a locked in-place fallback with weaker crash/power-loss guarantees; external editors that ignore the lock protocol are outside transaction protection.
- Named-session defaults are 24h idle TTL and 10,000 bindings; IDs accept 1–64 `[A-Za-z0-9_-]` characters. `http://wang.account01:1234@127.0.0.1:2323` uses the configured listener password, not a separately registered account. Bindings follow node identity across refresh/reload but are cleared on process restart.
- Sessions fix an upstream node, not its provider's public exit IP. Existing connections are not migrated and application requests are not replayed. Manual bans now remain until expiry/manual release; a failed/empty subscription provider keeps the previous complete subscription set.

Delivery continues through GitHub source archives and GHCR `linux/amd64`/`linux/arm64` images; this release does not attach standalone binary assets.

### Validation scope

Local validation uses temporary configuration, synthetic nodes/MMDB, and loopback services—not live subscriptions, public throughput, or long-running production soak tests. The publication workflow gates image building on default/production-tag tests, race/vet, UI/entrypoint fixtures, reachable vulnerability checks, and Linux amd64/arm64 builds. GitHub Actions records the actual remote check/image outcomes.
