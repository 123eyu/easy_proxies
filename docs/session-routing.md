# 会话路由使用指南

## 一个端口，两种用法

在 `pool` 或 `hybrid` 模式下，主 listener 端口（默认 `2323`）同时支持 HTTP 和 SOCKS5。用户名保持原样时使用普通池调度；加上 `.sessionID` 后，按认证用户与会话 ID 为 TCP 连接固定上游节点。

```yaml
listener:
  address: 0.0.0.0
  port: 2323
  username: wang
  password: "1234"  # 仅为示例，请更换密码

sticky:
  session_enabled: true
  session_ttl: 24h
  max_sessions: 10000
  enabled: false
  port: 2324
```

该片段补充已有配置；还需要配置实际可用的节点、节点文件或订阅。

| 地址 | 路由方式 |
| --- | --- |
| `http://wang:1234@127.0.0.1:2323` | 普通调度，遵循 `pool.mode` |
| `http://wang.account01:1234@127.0.0.1:2323` | 固定会话 `account01` |
| `http://wang.account02:1234@127.0.0.1:2323` | 另一条独立会话 |
| `socks5h://wang.account01:1234@127.0.0.1:2323` | 同一会话，通过 SOCKS5 访问并由代理解析域名 |

`0.0.0.0` 是监听地址，不是客户端连接地址。其他机器访问时，将 `127.0.0.1` 换成代理服务器的实际地址，端口随 `listener.port` 调整。

## 会话 ID 与认证

- ID 支持 1–100 个英文字母、数字、下划线或连字符，即 `[A-Za-z0-9_-]{1,100}`。
- ID 可任意指定，无需添加账号或事先注册。复用同一 ID 可复用绑定，首次连接时才选取节点。
- 同一用户的同一 ID 可跨来源 IP、HTTP/SOCKS5 连接复用；客户端来源 IP 不参与主端口会话身份。
- 不同 ID 是独立绑定，并不保证获得不同节点。节点数量不足时共享节点是正常行为。
- 密码始终使用 listener 原密码。会话 ID 不是密码，也不赋予额外权限。
- 会话路由的认证前提是 listener 用户名非空；密码沿用原配置，兼容旧版空密码，但建议设置非空强密码。
- ID 不支持空串、点号、空格、中文或其他符号；错误格式及错误密码会导致认证失败。
- 若配置的普通用户名本身带点，完整用户名仍按普通账号认证；会话格式为“完整用户名 + 点号 + ID”。
- 用户名或密码包含 URL 保留字符时，需要进行百分号编码；客户端提供独立用户名/密码字段时，直接填写原值。
- SOCKS5 的用户名与密码字段各限 255 字节，`基础用户名 + 点号 + 100 位 ID` 也必须落在该上限内；接近上限时改用 HTTP 入口或缩短 ID。

使用示例：

```bash
# 重复执行：同一会话保持同一节点。
curl --proxy 'http://wang.account01:1234@127.0.0.1:2323' https://example.com

# 使用另一个 ID：建立独立绑定。
curl --proxy 'http://wang.account02:1234@127.0.0.1:2323' https://example.com

# SOCKS5 与 HTTP 共用 account01 的绑定。
curl --proxy 'socks5h://wang.account01:1234@127.0.0.1:2323' https://example.com
```

`socks5://` 与 `socks5h://` 都使用 SOCKS5；后者让 curl 把目标域名交给代理解析，适合避免本地 DNS 结果影响连接。

## 从管理面板开始

1. 打开管理地址（默认 `http://127.0.0.1:9091`），启用管理密码时先登录。
2. 进入**会话路由**页，选择普通调度或命名会话；命名会话可自填 ID 或生成随机 ID。
3. 选择 HTTP/SOCKS5，生成接入地址，复制完整 URL 或 curl 命令到客户端。看板也提供接入快捷卡片。
4. 页面预览隐藏密码，但复制内容包含原代理用户名和密码；不要将其粘贴到公开日志、截图或 issue。页面不会把生成的代理密码写入 localStorage。
5. 实际使用代理并成功拨号后，在绑定列表查看节点、最近使用/空闲到期时间、切换次数和原因；可搜索会话。
6. 需要重新选节点时使用单项**重置**或**重置全部**并确认。重置只清除命名绑定，下次新连接重新选择，现有连接不迁移或关闭，也不保证一定选到不同节点。

未启用主池入口、未配置 listener 用户名或关闭了会话路由时，页面会显示具体原因。生成 URL 不代表连接测试成功，节点可用性请结合探测结果判断。启动日志中的接入 URL 使用密码掩码，需要实际认证信息时从面板复制完整地址。

## 节点选择与失败切换

1. 首次实际拨号时，按当前池调度策略选择可用节点，拨号成功后建立绑定。
2. 后续新连接继续使用绑定节点，而不是每次重新轮换。
3. 节点不可用、进入冷却/黑名单或从池中移除时，后续连接重新选择节点。
4. 拨号失败时，遵循 `pool.retry_enabled` 与 `pool.retry_attempts` 的重试策略；成功切换的节点成为新的会话绑定。
5. **绑定节点自身拨号失败时，本次请求会额外重新选一次节点**，即使 `retry_enabled: false` 或重试次数已用完。原因是失败的拨号来自失效绑定，而不是池调度本身；否则一条会话可能长期固定在一个已经不可用的节点上，每次连接都返回 502。
6. 若额外那一次也失败，仍保留原绑定（不会因为一次抖动就悄悄更换出口），下一次连接继续尝试；连续失败不会再刷新绑定的空闲时长。
7. 这次失败还会**立刻拉黑**该绑定节点（`pool.blacklist_failed_pin`，默认 `true`；设为 `false` 则回到 `failure_threshold` 累计逻辑，自动换节点重试不受影响）：真实的传输层故障（握手/证书/协议错误、拨号被拒）按 `pool.blacklist_duration`（默认 24h）直接进入黑名单，不必等到 `pool.failure_threshold` 次数累计，其它会话和普通调度都不会再选中它；`429` 与超时/连接重置/`503` 属于配额和瞬时问题，只按 `pool.rate_limit_cooldown`、`pool.transient_cooldown` 冷却，不长期拉黑。需要提前放回池子时，用面板或 `POST /api/nodes/{tag}/release`。

这里保证的是固定**上游节点身份**，不保证节点服务方始终使用同一个公网出口 IP。远端节点自身的出口轮换仍可能改变目标网站观察到的 IP。

失败切换发生在连接选择/建立阶段。已建立的 TCP 隧道不迁移，已发送的 HTTP 请求和响应不重放；目标网站的 4xx/5xx 等业务响应也不触发会话切换。应用需要重试时，应自行判断请求是否可安全重试。

固定绑定适用于 HTTP、HTTPS CONNECT 和 SOCKS5 CONNECT 的 TCP 连接。SOCKS5 UDP 请求可优先使用已有 TCP 绑定且支持 UDP 的节点；节点不支持 UDP 或请求需要回退时，会为该请求选择其他节点而不修改 TCP 绑定。因此不保证 UDP 永久使用同一节点或公网出口。

## 绑定生命周期与内存上限

| 配置/事件 | 行为 |
| --- | --- |
| `sticky.session_enabled` | 省略时为 `true`；显式设为 `false` 时关闭主端口用户名会话功能 |
| `sticky.session_ttl` | 默认 `24h`，按会话空闲时间释放，不是从首次创建起固定 24 小时更换节点；有效正时长不超过 `8760h` |
| `sticky.max_sessions` | 默认 `10000`，有效容量为 `1–100000`；触及上限时清理最近最少使用的绑定（LRU） |
| 订阅刷新 / 核心重载 | 使用 manager 生命周期内的存储，仍存在的相同 URI 稳定身份保留绑定 |
| 节点 URI 实质变化或节点移除 | 原绑定不再指向可用身份，后续连接重新选取 |
| 进程重启 / 容器重建 | 内存会话清空，首次新连接重新绑定 |

同一节点的显示名称或 URI 查询参数顺序变化不应被当作新节点。VMess base64 JSON 链接还会忽略 `ps` 显示名称、顶层 JSON 字段顺序以及支持的标准/URL-safe、带/不带填充 base64 编码差异。修改地址、凭据或实际传输参数则可能形成新身份。URI 稳定身份用于跨核心实例匹配，不在会话列表中暴露上游凭据。

多端口/混合模式的旧 `node_ports.json` key 会在加载时自动迁移到归一化身份并复用既有端口，不需要通过删除映射文件完成升级；端口映射持久化与命名会话进程内存储是不同机制，前者在进程重启后仍保留，后者会清空。

TTL 和容量清理可能释放绑定，因此该功能不是永久租用一个出口。被释放的会话 ID 仍可继续使用，下一次连接会重新建立绑定。只有**成功拨号**才刷新空闲时长；仅仅携带该用户名发起连接但拨号失败不会续期，因此长期失败的会话会按 `session_ttl` 正常过期。已有长连接中的持续流量不续期，不代表绑定一定不会空闲过期。

TTL 使用 Go 时长格式，如 `30m`、`2h`、`24h`；不要填写 `1d` 或 `24小时`。查看绑定列表和生成接入链接不会延长空闲时长。

绑定保留与连接不中断是两件事：核心重载/订阅刷新仍可能中断现有连接，但下次连接可继续复用保留的节点身份。

## 旧 `2324` 来源 IP 粘性入口

已有客户端继续使用原配置：

```yaml
sticky:
  enabled: true
  port: 2324
```

此处 `enabled` 和 `port` 只控制旧版独立入口，与主端口的 `session_enabled` 相互独立。旧入口复用 listener 地址与普通用户名/密码，按**客户端来源 IP** 绑定，而不是按 `.sessionID` 后缀。`session_ttl`、`max_sessions` 只管理主端口的命名会话，不改变旧 IP 绑定的生命周期。

例如 `http://wang:1234@127.0.0.1:2324` 延续原行为。多个程序或设备经同一个 NAT 出口连接时会共享 IP 绑定；需要同一设备同时使用多条独立会话时，改用主端口的用户名会话方式。

## 管理 API

这些接口复用现有管理面板登录认证，管理登录会话与代理路由会话是不同概念。`management.password` 为空时无需管理登录；启用后先通过 `/api/auth` 登录，再携带其 Cookie 或 Bearer token。

| 接口 | 用途 |
| --- | --- |
| `GET /api/proxy-sessions` | 查看命名会话绑定；返回 `enabled`、`reason`、`total`、`ttl`、`max_sessions` 和 `sessions` |
| `POST /api/proxy-sessions/links` | 生成接入 URL；请求字段为 `session_id`、`scheme` |
| `DELETE /api/proxy-sessions/{id}` | 重置单个绑定；`id` 是完整用户名，例如 `wang.account01`，作为单一路径段进行 URL 编码 |
| `DELETE /api/proxy-sessions` | 重置全部命名会话绑定，不清除旧来源 IP 入口的绑定 |

生成 URL 示例（以下按未设置管理密码的本地配置演示）：

```bash
curl -sS -X POST http://127.0.0.1:9091/api/proxy-sessions/links \
  -H 'Content-Type: application/json' \
  -d '{"session_id":"account01","scheme":"http"}'
```

响应包含 `url`、`masked_url`、`username`、`session_id`、`scheme`、`enabled`。`url` 含实际代理密码，应按凭据保管；`masked_url` 隐藏密码，适合界面预览。`scheme` 支持 `http` 或 `socks5`，省略时为 `http`；curl 使用代理侧 DNS 时，可将返回的 `socks5://` 地址改为 `socks5h://`。`session_id` 为空时生成普通调度地址。

URL 的主机优先使用 `external_ip`，否则采用访问管理面板的主机名，最后回退到回环地址；不会把 `0.0.0.0` 导出为客户端连接地址。反向代理域名与代理实际地址不一致时，配置正确的 `external_ip`。

已有 `/api/export` 同样生成可供客户端使用的本地代理 URL：替换通配地址、正确括起 IPv6，并对用户名/密码中的特殊字符进行百分号编码。原有健康节点筛选、`all=true` 和池/GeoIP 入口导出行为保留；它不创建命名会话，需要固定会话地址时使用 `/api/proxy-sessions/links`。

生成链接不连接上游、不预先绑定节点，因此会话列表在首次成功拨号前不会出现该 ID。列表包含完整用户名 ID、稳定节点身份、节点 Tag/名称、创建/最后使用/空闲到期时间、切换次数与最近原因，不返回上游 URI 或上游密码。

```bash
# 查看已有绑定。
curl -sS http://127.0.0.1:9091/api/proxy-sessions

# 重置一个绑定；下次新连接重新选择，现有连接不受影响。
curl -sS -X DELETE http://127.0.0.1:9091/api/proxy-sessions/wang.account01
```

重置的单个绑定不存在或已过期时返回 `404`。生成链接时，ID 或 scheme 格式错误返回 `400`；命名会话路由未开启或当前模式没有主池入口时返回 `409`，响应会给出原因。

命名会话链接需要路由存储初始化完成，否则返回 `503`；普通入口链接仍可生成。链接生成接口接收单个 JSON 对象，正文大小上限为 4 KiB。

## 常见问题

### 加后缀后认证失败

检查运行模式是否为 `pool`/`hybrid`，是否连接主 listener 端口、listener 是否配置了非空用户名、客户端密码是否与原配置一致，以及 `session_enabled` 是否开启。ID 必须符合上述字符和长度限制。旧独立端口、multi-port 直连端口和 GeoIP 独立入口不等同于主端口会话入口。

### 同一 ID 出口改变了

检查绑定节点是否失败、冷却、拉黑、被移除，是否超过空闲 TTL/触及容量清理，以及程序是否重启。若绑定节点没有改变，仍可能是远端节点提供方改变了公网出口。

### `wang.abc_1` 认证通过但一直 502，`wang.abc-1` 却正常

下划线和短横线在会话 ID 里语义完全相同（都只是 `[A-Za-z0-9_-]` 里的普通字符，不会被当作分隔符或通配符），两者不会因为字符不同而走不同分支。真实原因通常是**该 ID 的绑定节点已经不可用**：会话绑定的是上一次拨号成功时的节点，节点失效后不会因为换了写法而自动换节点。区分办法：

1. `curl -sS http://127.0.0.1:9091/api/proxy-sessions` 看该 ID 的 `node_tag`，再到节点列表确认该节点 `available` 与 `last_failure`。
2. 用该节点的 multi-port 直连端口试一次，如果同样 502，说明是节点问题，与会话 ID 写法无关。
3. `curl -X DELETE http://127.0.0.1:9091/api/proxy-sessions/wang.abc_1` 重置该绑定，下一次连接会重新选节点。

认证失败（含 ID 非法、密码错误）返回 `407`；认证通过但上游拨号失败才是 `502`，两者不要混为一谈。新版在绑定节点拨号失败时会自动重新选一次节点并迁移绑定，不再需要手工重置。

### 不同 ID 使用了同一个节点

独立绑定不等于独占节点；每条新会话仍使用池调度策略，允许选择同一个节点。

### 第一次启动出现 `lookup server: NXDOMAIN`

`config.example.yaml` 的 `vless://uuid@server:443` 是格式示例，需要替换为真实节点。使用订阅或节点文件时，先配置好实际来源再移除该内联示例；仅添加订阅并不会自动删除内联节点。

Docker 默认挂载目录时，编辑的是 `data/config.yaml`。修改仓库根目录的 `config.yaml` 不会改变该容器当前读取的配置。
